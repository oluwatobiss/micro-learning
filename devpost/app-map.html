Lesson & Schema Data Contracts

Strict TypeScript interfaces in app/types/lesson.ts and app/types/media.ts define the system contracts.

Lesson (Canonical Aggregate Root)
Represents an entire standalone micro-learning lesson unit.
export interface Lesson {
  id: string;               // UUID or slug
  title: string;            // Lesson title
  author: string;           // Original author attribution
  sourceUrl?: string;       // Link to original source article
  sourceSnippet: string;    // Core thesis / summary
  estimatedReadMinutes: number; // Dynamic read time (~180 wpm)
  totalCards: number;       // Bound between 4 and 8 cards
  cards: LessonCard[];      // Ordered sequence of cards
  keyTakeaways?: string[];  // 2-4 completion takeaways
  version: number;          // Schema version for migrations
  createdAt: string;        // ISO timestamp
}
LessonCard (Atomic Learning Card)
Individual card containing Markdown, code block, diagram, or checkpoint.
export interface LessonCard {
  id: string;               // Stable identifier (e.g. card-1)
  order: number;            // 1-indexed card order
  type: CardType;           // 'narrative'|'code'|'comparison'|'checkpoint'
  title: string;            // Concept heading
  content: string;          // GFU Markdown & code blocks
  visualMedia?: InstructionalMediaSpec; // ProcessFlow / Comparison
  checkpoint?: CheckpointData;          // Present if checkpoint
  isLocked?: boolean;       // Guarded against regeneration
}

The 5-Stage Adaptive Generation Engine

Implemented in app/services/generator.ts, transforming unformatted source text into a structured, high-retention micro-learning deck through 5 verifiable stages.

Stage 1: Understand Source
Stage 1
Extracts thesis, code snippets, key terms, process steps, and comparisons via disciplined AST-like structural parsing.
  • Method:understandSource(input)
  • Invariants:Thesis length > 20 chars; extracts verbatim code fences; deduplicates technical terms.
Stage 2: Adaptive Lesson Planning
Stage 2
Dynamically computes optimal card count (4 to 8 cards) based on source word count and structural density.
  • Method:planLesson(analysis, input)
  • Invariants:Strict card count bound: 4 <= targetCardCount <= 8; allocates card archetypes.
Stage 3: Creating Grounded Cards
Stage 3
Synthesizes narrative Markdown cards, grounded code examples, and structured media specifications.
  • Method:createCards(plan, analysis, input)
  • Invariants:Preserves code indentation and syntax; validates ProcessFlowSpec / ComparisonSpec.
Stage 4: Strict Checkpoint Contract
Stage 4
Constructs grounded multiple choice question with exactly 1 correct answer, 3 distractors, and explanation.
  • Method:createCheckpoint(analysis, input)
  • Invariants:4 options (A-D); correctAnswer in [0,3]; non-empty source-backed explanation.
Stage 5: Quality Audit & Scoring
Stage 5
Evaluates lesson across 100-point rubric checking thesis grounding, card count, code fences, and takeaways.
  • Method:auditLessonQuality(lesson, analysis)
  • Invariants:Deterministic scoring (0-100); classifies Defensible vs Needs Review.

State & Storage Isolation Architecture

Clean partitioning across localStorage keys ensures that in-progress editor drafts never bleed into saved lessons, and reader progress resets cleanly on version increments.

Storage KeyServiceLifecycleIsolation Guarantee
microlearning_lessons_v3 app/services/storage.ts Persistent canonical library. Seeded on first boot. Read-only to editor until explicit Save Lesson or Save & View in Reader action.
microlearning_editor_draft_{id} app/services/draft.ts Transient in-progress editing session. Survives reload. Fully isolated per lesson. Cleared automatically upon saving to canonical library.
microlearning_reader_progress_v1 app/services/progress.ts Reader progress (card index, answered checkpoint states). Version-aware: if lesson version increments, stale progress resets to card 0.
microlearning_theme app/root.tsx Global theme preference (clean-light, focused-dark, warm-editorial). Synchronously sets data-theme attribute on preventing flash of unstyled content.

Project-Grounded Practice: Extending the Quality Audit Rubric

Objective: Extend the deterministic 5-Stage Adaptive Generation Engine by adding a new automated quality check to Stage 5 (Quality Audit).

Micro-learning research demonstrates that cards with under 20 words lack context, while cards over 150 words cause cognitive fatigue. In app/services/generator.ts, add an audit check verifying average word count per card is in the sweet spot (30-120 words).

Implementation Guide:

  1. Open app/services/generator.ts and locate auditLessonQuality(lesson, analysis).
  2. Calculate average word count: const avgWords = Math.round(lesson.cards.reduce((sum, c) => sum + countWords(c.content), 0) / lesson.cards.length);
  3. If avgWords >= 30 && avgWords <= 120, award 10 points: rubric.push({ criterion: 'Card Readability & Density', maxPoints: 10, awardedPoints: 10, feedback: `Optimal micro-learning density (${avgWords} words/card average).` });
  4. In tests/generation.test.mjs, add assertion: assert.ok(report.rubric.some(r => r.criterion.includes('Density')), 'Must evaluate card word density');
  5. Run npm test to verify zero errors and clean output!
